# Crumple agent instructions

Crumple is an interactive, hand-drawn landing page for Yeet Factory: a
scroll-driven three.js scene on a sheet of paper. It is a standalone project;
the main Yeet Factory site lives in the `landing` repo and shares this tooling.

## Repository basics

- Package manager: Bun; use the version pinned in `package.json`. Do not use
  npm, pnpm or yarn.
- Stack: TanStack Start (React 19, file-based routing) built with Rsbuild,
  three.js with cannon-es physics, Tailwind CSS 4, and strict TypeScript 7.
- Layout: `src/routes` (routes and `<head>`), `src/components` (DOM layer),
  `src/engine` (the three.js scene), `src/lib` (scroll timeline, shared store,
  sound) and `src/site.ts` (name, domain and founders). Import from `src` with
  the `#/` alias.
- `src/routeTree.gen.ts` is generated by TanStack Router during `dev` and
  `build`. Commit it, but never edit it by hand.

## Rendering and deployment

- Cloudflare Pages builds with `bun run build` and serves `dist/client`. Every
  push to `main` deploys to production at crumple.yeetfactory.top.
- The homepage is prerendered; pages are listed under `pages` in
  `rsbuild.config.ts`. `dist/server` is a build by-product and is not deployed.
- The canvas draws the visuals. The DOM sections set the scroll length of each
  part and carry screen-reader text, so the page must still make sense without
  the canvas and during prerendering (no `window` or `localStorage` at render
  time).

## Commands

- `bun run dev`: start the dev server on port 3000.
- `bun run build`: build and prerender the site into `dist/client`.
- `bun run preview`: serve the built site locally.
- `bun run format`: check formatting. `bun run format:write` applies it.
- `bun run lint`: run Oxlint.
- `bun run typecheck`: type check with Bun's built-in TypeScript 7 checker.
- `bun run knip`: report unused files, dependencies and exports.
- `bun run test`: run the Bun tests in `tests`.
- `bun run check`: run format, lint, typecheck, knip and tests together.

## Execution and verification

- Keep changes within the requested scope and preserve unrelated user changes.
- Before adding complexity for a speculative or vanishingly unlikely edge case,
  explain the concrete failure mode, likelihood and complexity cost to the user
  and get their buy-in. Do not silently expand scope for theoretical
  robustness.
- Follow user instructions and project conventions over generic skill guidance.
- Fix lint and type errors at their source; do not suppress checks, disable
  rules or weaken them to make a change pass.
- Run `bun run check` and `bun run build` before calling a change done. The
  scene has little test coverage, so also load the page and exercise what you
  changed: the YEET button, the lever, grabbing letters, the sound toggle and
  the final crumple.

## Dependencies

- `package.json` and `bun.lock` are authoritative for versions. Check the
  installed package and its documentation or types before applying
  version-specific guidance.
- Add or upgrade dependencies only when the task needs it, and avoid unrelated
  upgrades.

## Tooling notes

- Formatting runs through `bun fmt` with `.oxfmtrc.json`. It sorts imports and
  Tailwind classes; there is no Prettier in this project.
- Import Fontsource stylesheets without the `.css` extension in
  `src/styles.css`. With the extension, the Tailwind class sorter cannot
  resolve the stylesheet and formatting fails.
- Type checking uses `bun check`. Keep the `typescript` package on the same
  version as Bun's checker (`bun -e 'console.log(process.versions.typescript)'`)
  so editors and the checker agree.
- `oxlint` and `@oxlint/plugins` must stay on the same exact version; upgrade
  them together.
- `tools/oxlint/anti-slop` is a vendored lint plugin. Do not edit it by hand;
  see its `UPSTREAM.md` for the source revision and update notes.
- The anti-slop rules ban `shape` in symbol names, including object keys. Name
  three.js and cannon-es shapes by their role (`profile`, `plate`, `collider`)
  and attach physics shapes with `body.addShape(...)` instead of the `shape`
  constructor option.
- Git hooks (`lefthook.yml`) only check staged files and typecheck before a
  push. They never rewrite files or change the staging area.

## Agent skills

- Skills are installed with the `skills` CLI (skills.sh). The files live in
  `.agents/skills/<name>`, `.claude/skills/<name>` is a symlink to them, and
  `skills-lock.json` records each source and hash. Commit all three.
- Add a skill with
  `bunx skills add <owner>/<repo> --skill <name> -a claude-code -a codex -y`.
  Both agent flags are needed to get the `.agents` copy plus the `.claude`
  symlink.
- Update with `bunx skills update -p`. Do not edit installed skills by hand.
